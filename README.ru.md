# Skill Picker

**Скилл для Claude Code, который подбирает, проверяет и ставит скиллы, реально нужные стеку вашего проекта, и показывает, что покрыто.**

Skill Picker это скилл для Claude Code, Codex, OpenCode, Cursor и других агентов, которые понимают
Agent Skills. Он подбирает, ставит и проверяет скиллы уровня проекта для текущего проекта. Агент
раскладывает стек по слоям, для каждой технологии оценивает, насколько вероятно, что он напишет
устаревший код, находит официальные или просто сильные скиллы, читает каждого кандидата целиком,
прежде чем советовать, ставит только одобренное вами и отдаёт одну таблицу покрытия.

## Зачем

Знания модели о библиотеках отстают от их релизов, а у каждого проекта свой стек, поэтому полезный
набор скиллов у каждого проекта свой. Если подбирать по привычке, набор получается кривым.

- Есть скилл для стабильной библиотеки, который никому не был нужен.
- Нет скилла для протокола, который выпускает новую версию каждый месяц.
- Один из скиллов тихо отправляет отчёты об ошибках производителю.

Скилл превращает выбор в метод с доказательством за каждой строкой. Установленные версии, даты
релизов и собственные файлы скилла.

## Установка

| Агент | Команда |
|---|---|
| Claude Code, как плагин | `/plugin install skill-picker --marketplace nyxandro/skills` |
| Claude Code, Codex, OpenCode, Cursor и другие | `npx skills add nyxandro/skill-picker-skill` |
| Любой агент, вручную | Скачайте [архив `.skill` последнего выпуска](https://github.com/nyxandro/skill-picker-skill/releases/latest/download/skill-picker.skill) и распакуйте в папку скиллов агента |

Выберите один способ. Если поставить двумя, Claude Code загрузит скилл дважды.

<details>
<summary>Требования и другие способы установки</summary>

<br>

- Проверке раскладки нужен Python 3 и только его стандартная библиотека. Для поиска и установки
  нужны Node.js (`npx skills`) и GitHub CLI (`gh`).
- На шаге поиска названия технологий проекта уходят на skills.sh. Каждая команда `npx skills`
  запускается с `DO_NOT_TRACK=1`, поэтому собственная статистика CLI выключена.
- Установка плагина одной командой работает в Claude Code 2.1.275 и новее. На старой версии
  сначала добавьте каталог командой `/plugin marketplace add nyxandro/skills`, потом выполните
  `/plugin install skill-picker@nyxandro`.
- Версия в каталоге не закреплена, поэтому каждый коммит сюда приходит пользователям плагина как
  обновление. Выполните `claude plugin marketplace update nyxandro` и
  `claude plugin update skill-picker@nyxandro` или включите автообновление в
  `/plugin` → Marketplaces.
- С `npx skills` добавьте `-g`, чтобы скилл стоял во всех проектах. Чтобы поставить определённую
  версию, допишите её метку, например `nyxandro/skill-picker-skill@v1.0.0`.
- Можно и клонировать репозиторий, а в папку скиллов агента положить ссылку на папку
  `skill-picker/`. Сборка не нужна.

</details>

## Как пользоваться

Формулировка задаёт, насколько далеко идёт агент.

| Вы просите | Агент |
|---|---|
| *Что здесь покрыто скиллами, а что нет?* | Проверяет установленное, без поиска и без установки |
| *Подбери скиллы для этого проекта.* | Находит и проверяет кандидатов и останавливается перед установкой |
| *Поставь X и Y.* | Проверяет эти два и ставит их |

## Как работает

1. **Опись.** Читает манифесты, установленные версии из менеджера пакетов или lock-файла (никогда
   не угадывает), файлы деплоя и CI, инструкции для агентов и документацию, а также скиллы, которые
   уже стоят. Ничего не меняет.
2. **Слои.** Языки, слой агентов и LLM, внешние API, фронтенд, бэкенд, данные, тесты, сборка,
   деплой и CI, наблюдаемость, безопасность и процесс. Слои, не привязанные к фреймворку, тоже
   считаются. Проекту с агентом нужен скилл по устройству агентов, а не только по его фреймворку.
3. **Риск.** Для каждой технологии читает реестр и список изменений и записывает риск как
   последствие, например "я вызову методы, которых больше нет", а не голое "высокий".
4. **Поиск.** Что уже покрыто глобальными и встроенными скиллами, скиллы внутри установленных
   пакетов, короткий каталог проверенных скиллов, собственный репозиторий библиотеки и публичный
   каталог skills.sh.
5. **Проверка.** Читает каждого кандидата, включая скрипты. Кто автор и для кого, под какую версию
   написан, сверяется ли с живой документацией или это застывший слепок, отправляет ли что-то
   наружу сам, конфликтует ли с правилами проекта, сколько стоит в каждой сессии.
6. **Отчёт и остановка.** Таблица покрытия, потом каждый кандидат с тем, что даёт, что стоит, и
   рекомендацией. Без вашего согласия на конкретный список ничего не ставится.
7. **Установка.** Настоящая папка ложится в `.agents/skills/`, ссылка в `.claude/skills/`, запись
   в `skills-lock.json`. Скилл, который поставляется внутри пакета, подключается ссылкой из
   `node_modules` или виртуального окружения, чтобы всегда совпадать с установленной библиотекой.
   Потом раскладка проверяется ещё раз, и агент доказывает, что вне проекта ничего не поменялось.

Работает только на уровне проекта. Глобальные папки скиллов читаются и никогда не меняются.
Коммитов и пушей не делает, а если папка скилла ведёт за пределы проекта, останавливается и ничего
не трогает.

## Пример

Таблица покрытия для выдуманного проекта.

| Слой | Технология | Риск устаревшего кода | Чем покрыто |
|---|---|---|---|
| Агенты и LLM | Anthropic SDK | Высокий, я возьму параметры, переименованные в недавних релизах | ✅ `claude-api` |
| Внешние API | Telegram Bot API | Высокий, новая версия каждый месяц | ✅ `telegram-bot-development` |
| Фронтенд | React | Средний | ⚪ Скилла нет намеренно, документация смотрится под задачу |
| Данные | Prisma | Высокий, команды миграций поменялись | ❌ Кандидат ждёт вашего решения |

После таблицы идут слабые места, по строке на каждую строку с высоким риском без полного
покрытия, и то, что не сделано.

## Версии

Текущая версия записана в поле `metadata.version` файла `skill-picker/SKILL.md`, так что любая
установленная копия показывает, какая она. У каждой версии есть метка в git и
[выпуск](https://github.com/nyxandro/skill-picker-skill/releases) со своим архивом.
[CHANGELOG.md](CHANGELOG.md) рассказывает, что изменилось.

<details>
<summary>Тесты</summary>

<br>

```bash
uv run --with pytest python -m pytest test
```

Тесты работают без сети, на поддельных проектах и поддельной домашней папке во временном каталоге.
Они проверяют каждый дефект раскладки, о котором сообщает скрипт, случаи остановки и то, что
скрипт ничего не меняет. pytest нужен только для тестов, самому скиллу он не нужен.

</details>

<summary>Устройство репозитория</summary>

